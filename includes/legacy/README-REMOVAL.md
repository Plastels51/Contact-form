# Модуль совместимости с 2.x — как удалить

Эта папка существует ради одного: чтобы сайты, обновившиеся с версии 2.x,
продолжали работать до того, как их формы переведут на новый формат.
После миграции она не нужна.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `class-cfs-legacy.php` | точка входа: `CFS_Legacy::boot()` |
| `class-cfs-form-builder.php` | рендерер форм версии 2.x (шорткод с атрибутами) |
| `class-cfs-legacy-adapter.php` | конвертер старых атрибутов в шаблон 3.x |
| `class-cfs-legacy-scanner.php` | поиск старых шорткодов в контенте и виджетах |
| `class-cfs-legacy-wizard.php` | экран «Заявки → Миграция» |

## Как это подключено

Единственная связь с ядром — в главном файле плагина:

```php
if ( file_exists( CFS_PLUGIN_DIR . 'includes/legacy/class-cfs-legacy.php' ) ) {
    require_once CFS_PLUGIN_DIR . 'includes/legacy/class-cfs-legacy.php';
    add_action( 'plugins_loaded', array( 'CFS_Legacy', 'boot' ), 5 );
}
```

Модуль общается с ядром только через публичные хуки:

- `cfs_render_legacy_form` — ядро спрашивает, умеет ли кто-то отрисовать
  шорткод без `id`/`slug`; отвечает `CFS_Form_Builder::render_legacy()`;
- `admin_menu`, `admin_init`, `admin_enqueue_scripts` — экран миграции.

В ядре нет ни одного `require` этих файлов, ни одной проверки «а есть ли
legacy», ни одного упоминания `CFS_Form_Builder`.

## Порядок удаления

1. Откройте **Заявки → Миграция** и убедитесь, что список пуст:
   «Мигрировать нечего — шорткодов старого формата на сайте нет».
   Если что-то найдено — нажмите «Мигрировать», а затем при необходимости
   привяжите старые заявки к новым формам в том же экране.
2. Проверьте страницы с формами: шорткод должен выглядеть как
   `[contact_form id="12"]`.
3. Удалите папку `includes/legacy/` целиком.
4. Необязательно: уберите блок `if ( file_exists( … ) )` из
   `contact-form-submissions.php`. Без него плагин работает точно так же —
   проверка просто перестаёт что-либо находить.

Формы, заявки, письма и интеграции удаление никак не затрагивает.

## Что перестанет работать

- Шорткоды старого формата (`[contact_form fields="name*,phone*"]`) —
  вместо формы администратор увидит сообщение об ошибке, посетитель ничего.
- Экран «Миграция».

## Проверка после удаления

Прогоните тесты — все наборы должны остаться зелёными:

```bash
docker compose exec -T wordpress php -r "define('DOING_AJAX', true); define('WP_ADMIN', true); define('WP_USE_THEMES', false); require '/var/www/html/wp-load.php'; require '/var/www/html/wp-content/plugins/contact-form/tests/run-all.php';"
```

Набор `run-tests-legacy.php` при отсутствии папки пропускает свои проверки —
это ожидаемое поведение, а не ошибка.
